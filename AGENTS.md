## Agent skills

### Specification and decisions

Before planning features or changing product behavior, read `docs/brainstorming/README.md` and the relevant current specification. Record approved decisions promptly in the repository and their Linear decision issue; see `docs/brainstorming/AGENTS.md` for the update workflow. File and issue changes are authorized. Secondary technical and architectural choices within the agreed constraints are delegated: decide, validate in the MVP, and record the rationale. Changes to product scope or foundational constraints remain user decisions.

### Issue tracker

Issues are tracked in Linear, in the Creuza project under Personal (NAS). Read `docs/agents/issue-tracker.md` before fetching, creating, or updating issues.

### Triage labels

Use the five default triage labels on Linear issues. Read `docs/agents/triage-labels.md` when applying a triage role.

### Domain docs

Single-context layout: root `GLOSSARY.md` and `docs/adr/`. Read `docs/agents/domain.md` before exploring the codebase or proposing domain changes.
